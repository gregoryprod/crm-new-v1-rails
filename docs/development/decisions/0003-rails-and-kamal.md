# Решение 0003: Ruby on Rails 8 и деплой через Kamal 2

Статус: **предложено** 20.10.2026 (ветка `feat/rails-rewrite`), ждёт решения владельца.
Заменяет стек из [решения 0001](0001-stack-and-orm.md) (Next.js + Drizzle). Протокол доставки
из [решения 0002](0002-notification-worker.md) сохраняется без изменений.

## Контекст

Нужен механический деплой одной командой на сервер в РФ, единый язык для сервера, фоновых
задач и экранов, минимум зависимостей фронтенда. Владелец проекта со стороны агентства
выбрал Rails 8 + Kamal 2.

## Решение

- **Rails 8.1, Ruby 3.4**, PostgreSQL 17. Экраны — ERB и Hotwire Turbo, без собственного JS.
- **Схема не меняется.** Первая миграция Rails `AdoptDrizzleSchema` на пустой базе выполняет
  исходные SQL-файлы Drizzle (`db/drizzle/`) и пишет журнал Drizzle. На базе, которую уже
  мигрировала Node-версия, она только проверяет журнал. Дальше схема — `db/structure.sql`.
- **HTTP-контракт не меняется.** Пути, коды, JSON и заголовки безопасности прежние. Исходный
  `scripts/smoke-http.mjs` проходит против Rails без правок.
- **Уведомления:** таблица `outbox` и отдельный процесс `bin/rails notifications:work`
  (роль `worker` в Kamal). Solid Queue не подключаем: очередь уже есть, отдельный супервизор
  с процессами съел бы память на 2 ГБ сервере.
- **Пароли:** argon2id, существующие хэши проверяются без сброса.
- **Деплой:** Kamal 2, локальный registry (образ уходит по SSH), kamal-proxy с Let's Encrypt,
  accessories `db` (PostgreSQL 17) и `backup` (ежедневный `pg_dump`, 30 дней).

## Проверка совместимости (20.10.2026, синтетические данные)

- 45 тестов Minitest на реальной PostgreSQL.
- `scripts/smoke-http.mjs` из Node-проекта: 17 из 17 шагов.
- Импорт YClients: пробный прогон и итоговые таблицы (клиенты, питомцы, записи, услуги, смены,
  исходные карточки с SHA-256, аудит) совпадают с Node-версией `de8a6d3`.
- Проекции рабочего пространства: одинаковый `batchId` на двух датах среза (документы совпадают
  побайтно в каноническом JSON).
- Идентификаторы `legacyId`, HMAC-хэши, чек записи и argon2 совпадают с Node.

## Последствия

- Разработка на Next.js останавливается; открытые PR Next-ветки (#26 и др.) переносятся в Rails.
- Интерфейс `public/full-crm` остаётся JS-приложением до отдельного перевода на Rails.
- Кэш запросов ActiveRecord отключён: протоколы блокировок и `RETURNING` требуют свежих данных.
- В локальной папке `{vpc}` фигурные скобки ломают поиск файлов по маске; обходы описаны
  в [rails-guide](../rails-guide.md).

## Отклонённые варианты

- **Kamal поверх Next.js** — дешевле (1–2 дня), но владелец выбрал единый Rails-стек.
- **Solid Queue для уведомлений** — лишний процесс и таблицы при одной очереди.
- **Новая схема БД на Rails-конвенциях** — потребовала бы ETL и потеряла бы совместимость с данными.
