# Подключение квиза к CRM: `POST /api/leads`

В основном приложении доступен встроенный `/quiz`: заявка → каталог/окна → бронь в том же PostgreSQL-календаре. Ответ приёма дополнен `booking_token` (64 hex либо `null` для SPAM); передавай его только в JSON `/api/booking`, не в URL, логи или постоянное хранилище браузера. Подробности локального перехода, ограничения и backup — в корневом README. Этот документ ниже описывает также самостоятельное встраивание формы приёма.

Готовый модуль для страницы квиза: [lead-snippet.js](lead-snippet.js) (ES-модуль без зависимостей). Тест `tests/integration/quiz-snippet.test.ts` исполняет именно этот файл против настоящего обработчика, поэтому сниппет и контракт не расходятся.

## Что нужно от владельца перед подключением

Эти значения не выдумываются и не имеют production-умолчаний — их задает владелец в окружении сервера:

| Переменная | Что это |
|---|---|
| `LEADS_ALLOWED_ORIGINS` | Точные origin страниц с квизом через запятую, например `https://<домен сайта>`. Без пути, без `*`. |
| `CONSENT_PD_VERSION` | Версия опубликованного документа оферты/обработки ПДн, на который ссылается обязательный чекбокс. |
| `CONSENT_MARKETING_VERSION` | Версия текста маркетингового согласия. |

Ссылки на документы в чекбоксах квиза задает сайт; сервер записывает только версию из окружения и время согласия (по часам БД). Пока любое из трех значений не задано, endpoint отвечает `503 intake_unavailable`.

## Встраивание

```html

  <input name="first_name" required maxlength="100" autocomplete="given-name">
  <input name="phone" type="tel" required maxlength="32" autocomplete="tel">
  <select name="species" required>
    <option>собака</option><option>кошка</option><option>грызун</option><option>птица</option><option>другое</option>

    Принимаю <a href="ССЫЛКА_НА_ОФЕРТУ">оферту</a> и даю согласие на обработку персональных данных</label>
  <!-- Отдельный необязательный чекбокс; по умолчанию выключен. -->
  <label><input type="checkbox" name="consent_marketing"> Согласен получать новости и предложения</label>
  <!-- Honeypot: скрыт от людей, боты его заполняют. Не используйте display:none у родителя формы. -->
  <div aria-hidden="true" style="position:absolute;left:-10000px;width:1px;height:1px;overflow:hidden">
    <label>Сайт <input name="website" tabindex="-1" autocomplete="off"></label>
  </div>
  <button type="submit">Отправить</button>
</form>
<script type="module">
  import { createLeadSubmitter } from "/js/lead-snippet.js";

  const submit = createLeadSubmitter({
    endpoint: "https://<домен CRM>/api/leads",

  document.getElementById("quiz").addEventListener("submit", async (event) => {
    event.preventDefault();
    const form = new FormData(event.currentTarget);
    const button = event.currentTarget.querySelector("button");
    button.disabled = true;
    const result = await submit({
      lastName: form.get("last_name"),
      firstName: form.get("first_name"),
      phone: form.get("phone"),
      species: form.get("species"),
      consentPd: form.get("consent_pd") === "on",
      consentMarketing: form.get("consent_marketing") === "on",
      website: form.get("website"),
    });
    button.disabled = false;
    if (result.ok) {
      // показать «Спасибо, мы свяжемся с вами»
    } else if (result.status === 400) {
      // подсветить поля из result.fields
    } else {
      // «Не удалось отправить, попробуйте еще раз» — повторная отправка тех же ответов использует тот же ключ
    }
  });
</script>
```

## Контракт

Запрос: `POST`, `Content-Type: application/json`, без cookies (`credentials: "omit"`), тело ≤ 8 КиБ.

| Поле | Тип | Правило |
|---|---|---|
| `last_name`, `first_name` | string | обязательно; пробелы обрезаются, 1–100 символов, нужна хотя бы одна буква, без управляющих символов |
| `phone` | string | обязательно; ≤ 32 символов из `0-9 + ( ) - .` и пробелов; нормализуется в E.164 (libphonenumber-js, регион RU по умолчанию), невалидный номер — 400 |
| `species` | string | обязательно; 1–50 символов; хранится как пришло, категория для отчетов вычисляется по справочнику (собака, кошка, грызун, птица, другое) |
| `consent_pd` | boolean | обязательно `true` |
| `consent_marketing` | boolean | необязательно, по умолчанию `false`; хранится отдельной записью согласия |
| `quiz_version` | string | обязательно; `[A-Za-z0-9_.:-]`, до 64 |
| `idempotency_key` | string | обязательно; `[A-Za-z0-9_-]`, 16–128 (UUID подходит); один ключ на одни ответы, повторяется при ретраях |
| `utm` | object | необязательно; сохраняются только `source`, `medium`, `campaign`, `content`, `term` до 100 символов; значения, похожие на email/телефон, отбрасываются |
| `page_url` | string | необязательно; сохраняются только схема, хост и путь (без логина/пароля, query и fragment); путь с email/телефоном заменяется на `/` |
| `website` | string | honeypot: должно быть пустым |

Неизвестные поля игнорируются и не сохраняются. В `raw_payload` попадают только известные очищенные поля (без заголовков, IP, лишних UTM и содержимого honeypot).

Ответы (тело никогда не содержит введенных значений):

| Код | Тело | Когда | Повторять? |
|---|---|---|---|
| 201 | `{"lead_id":"…","status":"created"}` | создана заявка или повтор того же ключа с теми же данными (заголовок `Idempotent-Replayed: true`) | нет |
| 400 | `{"error":"invalid_request","fields":[…]}` | ошибки полей (только имена) | после исправления |
| 403 | `{"error":"forbidden_origin"}` | Origin не из списка, `null` или отсутствует | нет |
| 409 | `{"error":"idempotency_conflict"}` | ключ уже использован для других данных/согласий | с новым ключом |
| 413 | `{"error":"payload_too_large"}` | тело > 8 КиБ (считаются реально полученные байты) | нет |
| 415 | `{"error":"unsupported_media_type"}` | не `application/json` | нет |
| 429 | `{"error":"too_many_requests"}` + `Retry-After` | превышен лимит | после `Retry-After` |
| 500/503 | `{"error":"internal_error"}` / `{"error":"intake_unavailable"}` | сбой / прием не настроен | да, с тем же ключом |

CORS: preflight `OPTIONS` разрешен только точному origin из `LEADS_ALLOWED_ORIGINS`, методу `POST` и заголовку `Content-Type`; `Access-Control-Allow-Credentials` не выдается. `Retry-After` доступен скрипту через `Access-Control-Expose-Headers`.

### Идемпотентность

- Сравниваются бизнес-поля: фамилия, имя, телефон (E.164, формат ввода не важен), вид, `consent_pd`, `consent_marketing`, `quiz_version`. UTM, страница и honeypot на сравнение не влияют.
- Версия документа согласия определяется сервером и в сравнение не входит: повтор после смены версии вернет прежний `lead_id`, новых согласий не появится.
- Повтор известного ключа не пишет в БД и не расходует лимит — в том числе одновременный: ключ блокируется advisory-lock и перепроверяется **до** расхода квоты, поэтому повтор или конфликт при исчерпанной квоте IP получает 201/409, а не 429.
- Конкурентные запросы с одним ключом создают ровно одну заявку, остальные получают тот же `lead_id` (или 409 при других данных).

### Ключи в сниппете

- Ключ хранится для каждого набора ответов отдельно, поэтому параллельные отправки разных ответов не влияют на ключи друг друга. ФИО и вид сравниваются так же, как на сервере (NFC, обрезка и схлопывание пробелов).
- Телефон без библиотеки нельзя привести к E.164, поэтому подпись телефона консервативна (`phoneSignature` в сниппете). Эквивалентны **только**: формы, отличающиеся пробелами и символами `( ) - .`; и для одного российского номера — `+7XXXXXXXXXX`, `8XXXXXXXXXX` и `XXXXXXXXXX` (10 цифр без «+»; сервер читает ввод без «+» в регионе RU, где «8» — префикс выхода). Ведущий «+» всегда значим: `4951234567` (+7 495…) и `+4951234567` (+49 51…) — разные ответы и разные ключи. Остальные формы без «+» (например, `7XXXXXXXXXX`) сравниваются буквально: для одного реального номера это лишь новый ключ (в худшем случае вторая заявка с меткой «возможный дубль»), но никогда не ложный 409. Тест сверяет подпись с серверной нормализацией на детерминированной выборке.
- Все повторы внутри одной отправки (сетевая ошибка, потерянный или нечитаемый ответ 201, 429 с `Retry-After` ≤ 30 с, 5xx) идут с одним ключом; двойной клик с теми же ответами отправляет один ключ и получает один `lead_id`.
- Повторная отправка тех же ответов — после успеха или после исчерпания попыток — снова использует тот же ключ и возвращает уже созданную заявку, а не дубль. Память живет до перезагрузки страницы (не более 50 наборов ответов).
- 409 забывает ключ только своих ответов и только если он еще текущий; следующая отправка этих ответов получит новый ключ.

### Антиспам и лимиты

- Лимит считает только **новые валидные** заявки (включая honeypot); невалидные (400), запрещенные (403/413/415) и повторы ключа не считаются и ничего не пишут.
- Окно `LEADS_WINDOW_MINUTES` (60): не более `LEADS_IP_MAX_PER_WINDOW` (10) с одного IP (HMAC; IPv6 по /64) и `LEADS_GLOBAL_MAX_PER_WINDOW` (300) всего. Запрос, отклоненный по IP, не расходует общий лимит.
- Состояние лимитов — таблица `rate_limits` в PostgreSQL (общая для процессов, переживает рестарт). Допуск выполняется внутри транзакции заявки под блокировкой строки общего окна (`FOR UPDATE`) и сериализован между процессами: отказ по общему лимиту не создает строку IP, отказ по IP не расходует общий лимит, а счетчики допущенной заявки откатываются вместе с ней при сбое. Строки IP создаются только допусками, поэтому живых строк за окно ≤ общий лимит + 1; на каждом допуске удаляется до 500 истекших строк IP, общая строка сбрасывается на месте. Порядок блокировок: ключ → общее окно → телефон.
- Цена сериализации: новые заявки создаются по одной во всей системе; для объема v0.1 (≤ общего лимита в час) это не узкое место.
- IP берется только из `X-Forwarded-For` при `TRUST_PROXY=true` (прокси должен перезаписывать заголовок). Без доверенного прокси IP неизвестен: `ip_hash` пуст, действует только общий лимит.
- Honeypot заполнен → ответ такой же `201`, заявка сохраняется со статусом `SPAM`, без события в outbox (уведомления не будет).
- Точка подключения капчи пока не реализована (открытый вопрос 4 архитектуры).

### Что создается

Одна транзакция: клиент (`possible_duplicate`, если телефон уже встречался) → ссылки на кандидатов в дубли (до 20 последних) → животное → заявка → согласия `PD_OFFER` и `MARKETING` (версия из env, время БД, `ip_hash`) → `audit_log` `lead.created` (без ФИО/телефона) → `outbox` `lead.created` с payload только `{"lead_id": …}`. Сбой на любом шаге, включая COMMIT, откатывает все.

## Ручная проверка на синтетических данных

```sh
curl -i -X POST http://127.0.0.1:3103/api/leads \
  -H 'Origin: http://127.0.0.1:3103' -H 'Content-Type: application/json' \
  -d '{"last_name":"Синтетова","first_name":"Тестина","phone":"+7 999 000-00-01","species":"собака",
       "consent_pd":true,"quiz_version":"manual-test","idempotency_key":"manual-test-key-0000000001"}'
```

Повтор той же команды вернет тот же `lead_id`; изменение `species` с тем же ключом — `409`.
